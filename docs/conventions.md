# Code Quality & Best Practices — Rationale

What's in here: the full "why" behind each code-quality rule condensed in CLAUDE.md's Code Quality Rules section. Read this when you need the reasoning behind a rule, not just the rule itself — CLAUDE.md has the imperative one-liner; this has the full explanation and examples.

This project follows production best practices throughout:

- **Backend constants** — all literals (numbers, strings, thresholds, weights, sentinel values) live in `app/constants.py`, except LLM prompt templates, which live in `app/llm/prompts.py` (kept apart so prompt-engineering diffs stay clean) and CSS-selector/scraping constants in `app/ingestion/selectors.py`. Cross-stack scalars (TTLs, locale set, weights, signals, category/vibe taxonomies) are sourced from `shared/app-config.json` and imported via `app._generated.shared_constants`. Never define a constant near business logic — always add it to `app/constants.py` (or `shared/` + regenerate) first, then import it. Never duplicate constants across files.
- **Backend utilities** — all shared helper functions live in `backend/app/routers/utils.py`. Before writing a new utility function anywhere in the backend, check this file first. If the function is reusable, add it here and import it — never duplicate helpers across routers or modules. **Exception:** `get_current_user` (`app/routers/auth.py`) and `get_current_organizer` (`app/routers/organizer_auth.py`) stay in their own auth router files rather than moving to `utils.py`. Both are FastAPI `Depends`-injected auth entry-points, each defined exactly once and imported by the routers that need it (`feed.py`, `feedback.py`, `browse.py`, `onboarding.py`, `organizer_events.py`) — there is no duplication for the rule's anti-duplication rationale to eliminate. `utils.py` already holds the closely-related `parse_session_cookie_user`, which decodes a session cookie into `(user_id, token_version)` without touching the DB or raising `HTTPException`; `get_current_user`/`get_current_organizer` layer a DB lookup, session-token-version revocation check, and router-specific `HTTPException` responses on top, making them full auth-flow entry points rather than generic serialization/parsing helpers, and better read alongside the magic-link/session code they share a module with. **Second exception:** `check_admin_lockout`, `record_admin_auth_failure`, `clear_admin_auth_failure`, `admin_username_disabled`, `admin_credentials_ok` (`app/routers/admin.py`) stay put and are imported cross-module by `app/routers/admin_auth.py`. They're inseparable from the module-level `_admin_auth_failures` LRU (also `admin.py`) and its evictor — moving the five functions without that state would split one invariant (the lockout counter and its eviction policy) across two files, and moving the state too would relocate admin-auth-specific data into a generic helper module that otherwise holds stateless functions. Documented in `docs/backend-ops.md`.
- **Frontend constants** — all magic values (numbers, strings, breakpoints, timeouts, limits) live in `frontend/src/constants.ts`. Cross-stack values (`LOCALES`, `PERSONAS`, `MAGIC_LINK_EXPIRY_MINUTES`, `PERSONA_PRIMARY_WEIGHT_THRESHOLD`) are sourced from `shared/` and imported via `frontend/src/_generated/sharedConstants.ts`. Apply the same discipline: never inline a literal near component logic — add it to `constants.ts` (or `shared/` + regenerate) first. Never duplicate constants across components.
- **Frontend utilities** — all shared helper functions live in `frontend/src/utils.ts`. Before writing a new utility function anywhere in the frontend, check this file first. If the function is reusable, add it here and import it — never duplicate helpers across components or pages.
- **CSS design tokens** — the following categories are fully tokenized in `:root` (`frontend/src/index.css`) and **must never be hardcoded** in component stylesheets: colors (semantic names, no common prefix — `--accent*`, `--bg*`, `--text*`, `--border*`, `--danger*`, `--success*`, `--on-accent`, `--overlay-scrim`, …), border-radius (`--radius`, `--radius-sm`/`-lg`/`-pill`/`-full`), shadows (`--shadow-*`), z-indices (`--z-*`), transitions (`--transition`, `--transition-transform`), animation easing + durations (`--easing`, `--easing-breathe`, `--anim-*`), blur (`--blur-*`), spacing (`--space-0-1`…`--space-9`, including fractional steps like `--space-1-25`), typography (`--fs-2xs`…`--fs-xl` plus role-specific `--fs-*`, `--heading-display`/`--heading-3xl`…`--heading-xs`, `--numeral-*`, `--leading-*`, `--tracking-*`, `--font-display`), and component-geometry vars (e.g. `--calendar-cell-size`, `--picker-pop-width`, `--toggle-*`, `--spinner-*`). When any of these are needed, define the token in `:root` first, then reference it via `var(--token-name)`. The token groups themselves, the light-theme (`:root[data-theme="light"]`) inversion rules, and the visual language they encode are documented in `docs/design-system.md`.
- **CSS shared base classes** — structural CSS patterns (card chrome, button styles, menu/popover chrome) live in `frontend/src/components/shared/` (`Card.module.css`, `Button.module.css`, `Menu.module.css`). Use CSS Modules `composes: baseClass from '...'` to inherit shared rules — **never duplicate card, button, or menu CSS** across route or component stylesheets. Add new shared patterns to the shared files and compose from them, as a base-class + modifier pair — never restyle an existing base class in place to suit one consumer. Module-by-module map in `docs/design-system.md`.
- **Retry logic** — all HTTP calls use `http_get()` / `http_post()` from `app/ingestion/http_client.py`, which wrap `httpx` with tenacity exponential-backoff retry (`HTTP_RETRY_MAX_ATTEMPTS` 5, `HTTP_RETRY_WAIT_MIN`–`MAX` 2–30s, plus up to `HTTP_RETRY_JITTER_MAX` 1s of jitter). A 429's `Retry-After` header is honored verbatim instead of the backoff curve, capped at `HTTP_RETRY_AFTER_MAX_SECONDS` (60s). Retryable: `HTTP_RETRYABLE_STATUS_CODES` (429/502/503/504) and `RequestError`. Non-retryable: 4xx except 429. **Exceptions** (six call sites bypass `http_get`/`http_post`, each for a documented reason — do not add a seventh without one): `app/auth/email.py` and `app/email/contact.py` call Resend directly because they're awaited inline in a user-facing request (`POST /auth/request-link`, `POST /contact`) — a 5-attempt tenacity backoff would stall the response by up to ~150s; `app/email/report_notify.py` and `app/email/report_reporter.py` call Resend directly for the same reason — `report_notify` is awaited inline in `POST /reports` (`routers/reports.py`), and `report_reporter` fires from `routers/utils.py::resolve_open_reports`, the shared helper every admin resolve/takedown request path funnels through; `app/llm/router.py` calls each `LLM_PROVIDERS` entry directly because the Groq→Cerebras→Mistral fallback chain *is* the retry strategy, and stacking tenacity backoff underneath it would fight the chain's own fast-fail-and-advance behavior; `app/logging_config.py` calls `httpx.Client` (sync) directly because it runs on the `QueueListener` background thread, which can't await the async `http_post`. Contrast `app/email/digest.py`, which sends inside a scheduled batch job (not a request path) and correctly routes through `http_post`.
- **DB connection pooling** — `app/db.py` sets `pool_pre_ping=True` (pings before reuse) and `pool_recycle=DB_POOL_RECYCLE_SECONDS` (280s, below Neon's 5-min idle auto-suspend) so the pool never hands out a connection the server has already dropped.
- **HTML listing adapters** — Piletilevi, KUMU, and Estonia Concert Hall share `HtmlListingAdapter` (`app/ingestion/sources/html_base.py`), which handles pagination, parsing, dedup, and detail fetches. New HTML-scraped sources should subclass it rather than duplicating the fetch/parse loop. Per-locale page discovery + the shared locale-variant fetch loop (`fetch_locale_variants`) live in `app/ingestion/locale_urls.py` — reused by `html_base.py`, `fienta.py`, and `refetch.py`; don't duplicate hreflang/locale-detection logic in an adapter. Low-level BeautifulSoup helpers (`attr_str`) live in `app/ingestion/html_utils.py`, kept separate from `html_base.py` to avoid a circular import with `locale_urls.py`.
- **Presentation layer separation** — never inline static CSS or HTML markup inside business-logic or delivery modules. Extract CSS into a dedicated `styles.py` and HTML markup into a dedicated `templates.py` sibling, then import the constants into the assembly module. The email package (`app/email/styles.py`, `app/email/templates.py`, `app/email/digest.py`) is the canonical example: CSS constants in `styles.py`, `.format()`-style markup constants in `templates.py`, data formatting + Resend delivery in `digest.py`. Apply the same three-file split to any future rendering feature (new email types, report generation, etc.). Do not introduce a templating engine (Jinja2, etc.) — plain Python string constants with `str.format()` are sufficient and keep dependencies minimal. **Exception:** `app/email/contact.py` is internal-only owner-inbox mail (no user-facing branding), so it inlines a small escaped-plain-markup body and skips the split — user-facing emails must not.
- **Encapsulation** — a leading underscore signals module-private; never import a `_name` from another production module *of ours*. If a helper is imported cross-module, drop the underscore to make the API surface honest. The rule is intra-project — a third-party library's own documented public export that happens to be spelled with a leading underscore (e.g. `slowapi`'s `_rate_limit_exceeded_handler`, imported by `app/rate_limit.py`) isn't ours to rename. Exceptions: `_is_retryable`, `_find`, `_venue_compatible`, `_make_slug` are intentionally private (used only within their defining module). Tests may import private names for white-box testing — that is an accepted pattern.
- **Error visibility** — HTTP failures in source adapters propagate to `SourceAdapter.run()` so `IngestionRun.error` and `source.last_status` are always set correctly. Never swallow exceptions in `fetch_raw()`.
- **Taxonomy** — LLM classification uses the fixed 14-category / 10-vibe frozensets `VALID_CATEGORIES` / `VALID_VIBES` (sourced from `shared/app-config.json` via `app/constants.py`). Filter LLM output against these frozensets before persisting — unknown values are silently dropped (see `_parse_classification` in `app/llm/classifier.py`).
- **Migrations** — always chain migrations correctly (`down_revision = "PREV"`). Keep migrations small and reversible. If a new unique index could collide with pre-existing duplicate rows (e.g. `event_sources(source_id, external_id)` in `0007`), include a defensive `DELETE` keeping the smallest `id` per key **before** `create_index` — never assume application-level gating prevents historical dupes.
- **Batch jobs — bulk-load, no N+1** — periodic jobs (`build_daily_feeds`, `classify_pending`, `run_dedup_pass`, `send_daily_digests`) must use a fixed number of queries independent of row count. Bulk-fetch all per-user / per-event data with one `WHERE col IN (...)` query and group in Python; never `SELECT` inside a `for user in users:` loop. When extending these jobs, group fetches before the inner loop, mirroring the pattern already in `ranking/score.py::build_daily_feeds` and `llm/classifier.py::classify_pending`.
- **External-API fan-out — bounded concurrency** — when sending many independent outbound calls (e.g. Resend digest emails), use `asyncio.gather(..., return_exceptions=True)` wrapped with an `asyncio.Semaphore` whose limit lives in `app/constants.py` (see `DIGEST_SEND_CONCURRENCY`). Pick the cap from the upstream provider's documented rate limit, leaving headroom for retries. Never serial-await one call at a time, and never unbounded-gather without a semaphore.
- **Dedup self-join pre-filter** — the shared `candidate_pair_ids_in_window()` helper (`app/dedup/rules.py`) SQL-pre-filters candidate pairs via an aliased self-join on a sargable `BETWEEN` time window. Both dedup passes consume it: `run_dedup_pass` (rule-only) feeds the pairs to `cluster_events`, and `run_dedup_pass_llm` (rule + LLM) runs the Python fuzzy `is_candidate_pair` check then the LLM tiebreaker on them. The Python fuzzy step always runs only on the pre-filtered pairs. Preserve this split: don't push the time check into Python, and don't push the fuzzy check into SQL.
- **Quote style** — Backend Python uses **double quotes** (enforced by Ruff `Q` rules in `backend/ruff.toml`: `inline-quotes`, `multiline-quotes`, `docstring-quotes` all set to `double`). Frontend TypeScript uses **single quotes** for JS/TS string literals and **double quotes** for JSX attributes (enforced by ESLint `quotes: ['error', 'single', { avoidEscape: true, allowTemplateLiterals: true }]` + `'jsx-quotes': ['error', 'prefer-double']` in `frontend/eslint.config.js`). Template literals and strings containing the preferred quote character may use the alternate form (`avoidEscape`). Run `ruff check --fix` and `eslint --fix` before committing.
- **Python lint rules** — Ruff is configured in `backend/ruff.toml` with `select = ["E", "F", "W", "Q"]` (pycodestyle errors/warnings, Pyflakes, quotes), `line-length = 88`, `ignore = ["E501"]` (long lines allowed when wrapping would hurt readability), and `extend-exclude = ["app/_generated"]` (generated modules are not hand-formatted). `python -m ruff check backend` must pass clean before commit. (`ruff` is not on PATH — always invoke via `python -m ruff`.)
- **Type checking** — `mypy` (`==2.1.0`, pinned in `backend/requirements-dev.txt`) must pass clean: `python -m mypy app` from `backend/`. No mypy config file exists — defaults are sufficient. A loop/result variable reused across blocks with structurally incompatible types (e.g. different ORM models) will fail under mypy's inference even though each block is independently correct; give each block its own variable name. Third-party imports with no type stubs (e.g. `apscheduler`) get a targeted `# type: ignore[import-untyped]` on the import line rather than a blanket per-module ignore.
- **Type annotations** — Use modern PEP 604 / PEP 585 syntax: `X | None` not `Optional[X]`, `list[T]` / `dict[K, V]` / `tuple[T, ...]` not `List` / `Dict` / `Tuple`. Annotate return types on all public functions (including FastAPI route handlers — `-> dict`, `-> list[Schema]`, `-> None`). Import from `typing` only for things still required there (e.g. `Any`, `TypeVar`, `Protocol`). **Exemption:** default-exported React components (`frontend/src/routes/*`, `frontend/src/components/*`) are not required to annotate their return type — ESLint does not enforce `@typescript-eslint/explicit-function-return-type` here and `tsc` infers the JSX return type exactly, so annotating all ~39 of them would be pure churn with no type-safety gain. This exemption is React-component-specific; non-component public functions still annotate their return types.
- **Shared test fixtures** — Common pytest fixtures (`mock_db`, `make_user`, `make_event`) live in `backend/tests/conftest.py`. Use them instead of inlining `AsyncMock()` DB scaffolding or constructing user/event objects by hand in each test. When a new fixture would be reused across two or more test files, add it to `conftest.py`.
- **Frontend test fixtures** — `renderWithProviders` (wraps in `QueryClient` + `MemoryRouter`) and `makeEvent` live in `frontend/src/test/utils.tsx`. Never inline `QueryClient`/`Router` scaffolding in a test — import from there. Mock the `api` module (`vi.mock('../../api/client')`) for component and route tests rather than mocking `fetch`.
- **Numeric truthiness** — never gate a numeric field on truthiness; `0` is falsy, so `price_raw.get("min") or fallback` and `raw.get("price") or {}` silently drop legitimate zero prices (free events). Use explicit `is not None` checks and `isinstance(x, dict)` guards. Currency normalization goes through `normalize_currency(raw, has_price)` in `app/ingestion/pricing.py`.
