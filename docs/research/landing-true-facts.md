# Landing True Facts

What's in here: a fact inventory for the Landing redesign (wayfinder #181, this ticket #183) — every durable, true, specific claim the Landing page could make about What's on Radar, each classified Static / Slow / Live, with the live-DB query or source file it came from. Input to the counts-endpoint ticket (#188); does not design that endpoint.

## Snapshot provenance

Queried via `PGPASSWORD=eventradar psql -h db -U eventradar -d eventradar -tAc "<SQL>"` against the devcontainer's local Postgres, **2026-08-31** (`select now()` → `2026-08-31 13:09:35+00`).

- `select status, count(*) from events group by status;` → published 1458, draft 587, classified 111, cancelled 90.
- All Landing-facing numbers below are scoped to `status = 'published'` per the ticket's rule, matching what `app/routers/public.py` / the public read paths actually return.
- **Data-freshness caveat (important):** `select created_at::date, status, count(*) from events where created_at >= now() - interval '45 days' group by 1,2 order by 1,2;` shows the dataset is dominated by a single bulk load on **2026-07-26** (1,381 of the 1,458 published rows were created that one day), with only a thin trickle afterward (29, 1, 7, 39, 1 published rows on scattered later days) and a fresh **unpublished** batch of 475+14 draft rows on 2026-08-25/26. `select min(created_at) from events;` → 2026-07-26 18:36 (dataset origin). `select max(created_at) from events where status='published';` → 2026-08-09 (newest *published* row); `select max(created_at) from events;` → 2026-08-26 (newest row of any status, still in the pipeline). **This looks like a seed/demo dataset, not a mature production ingestion history** — real per-week "new events" throughput cannot be honestly derived from this snapshot alone. Treat every "arrives every week" style claim below as unverifiable until re-checked against a production DB with weeks of organic scraper history.

## The strongest candidates for permanent/near-permanent copy

- **Static, hardcode freely:** "Five personalized picks, every morning at six" (#20/#22); "Available in English, Eesti, and Русский" (#27); "Organized across 14 categories" (#29).
- **Slow, safe to restate at each build without an endpoint:** venue count "200+ venues across Tallinn" (#5, use 205 not the miscounted 308); source roster "Fienta, Piletilevi, KUMU, Estonia Concert Hall — and organizers submitting directly" (#13/#14).
- **Live, must go through the counts-endpoint (#188), never hardcoded:** upcoming event count (#2, "over 1,000 events"); this-week count (#16); tonight count (#17, use with caution — can be a very small, unflattering number); date horizon (#4, restate periodically as "into 2027", not the literal date).
- **Explicitly do not ship:** the 308-venues figure (wrong scope, see #5); any "new events every week" ingestion-rate claim (#19 — this snapshot is a bulk seed load, not organic history, and the number would be fabricated); the €420 price ceiling (#12, embarrassing if surfaced); category/vibe long-tail counts like `romantic` (7) or `cinema` (5) (#7/#8, thin enough to undercut the "content density" goal if named individually).
