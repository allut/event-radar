# Frontend

What's in here: the routes/components/hooks folder structure, and the i18n data pipeline (shared JSON → generated TS/Python).

Read this before touching `frontend/src/routes/`, `frontend/src/components/`, `frontend/src/hooks/`, `frontend/src/lib/`, `shared/i18n/`, or `backend/app/email/`.

## Frontend Structure

Each component and route lives in its own folder containing `Name.tsx`, `Name.module.css`, and a one-line `index.ts` barrel (`export { default } from './Name'`). The barrel keeps import strings short — callers write `./components/EventCard`, not `./components/EventCard/EventCard`. **Exceptions:** `LocaleSelector/` has no `Name.module.css` — it fully delegates rendering to `SelectMenu` and has no styles of its own to hold; `Privacy/` and `Terms/` likewise have none, being one-line wrappers over `LegalPage` (which owns the styling).

- Routes (pages) in `frontend/src/routes/`: `Landing/`, `Login/`, `AuthVerify/`, `Onboarding/`, `Feed/`, `Explore/`, `SavedEvents/`, `EventDetail/`, `Settings/`, `Unsubscribe/`, `Privacy/`, `Terms/`, `Contact/`, `NotFound/`, plus the organizer portal's `OrganizerLogin/`, `OrganizerVerify/`, `OrganizerDashboard/`, `EventSubmit/` (routed at `/organizer/login`, `/organizer/verify`, `/organizer/dashboard`, `/organizer/submit`, and reused at `/organizer/events/:id/edit`). `Landing/` is the logged-out marketing page (own `RadarHero` subcomponent beside it, not a shared component); `App.tsx`'s `Home` picks `Landing` vs `Feed` off `useAuth()` — a live subscription, **not** a one-shot `isAuthenticated()` read, so signing out while already on `/` swaps the page instead of stranding a stale Feed. `Privacy/` and `Terms/` are one-line wrappers over the shared `LegalPage` component (which renders `TopBar` + a structured legal doc loaded per-locale from `frontend/src/content/legal/`, e.g. `privacy.en.ts`); `Contact/` renders its own `TopBar` + the contact form (via `useContactSubmit`). The organizer routes sit behind their own `OrganizerProtected` guard (`App.tsx`, mirrors `Protected` but reads `useOrganizerAuth()` and redirects to `/organizer/login`) — the user and organizer auth tracks never share a route guard, matching their separate token/salt tracks (see `docs/security.md`).
- Shared components in `frontend/src/components/`: `EventCard/`, `PersonaCard/`, `ErrorBoundary/`, `PageState/`, `LocaleSelector/`, `FeedbackButtonRow/`, `EmptyState/`, `Toast/` (transient success/error banner, driven by `useToast`), `TopBar/`, `OrganizerTopBar/` (top nav for the organizer portal routes, parallel to `TopBar/`), `MobileMenu/`, `Footer/`, `StaticPage/`, `LegalPage/`, plus the Explore filter-control primitives `Chip/`, `FacetMenu/`, `SelectMenu/`, `SegmentedControl/`, `Toggle/`, and the themed form controls `DatePicker/`, `SelectField/`, `FileField/`. `EventCard/index.ts` also re-exports `type EventData`. `TopBar/` is the shared top nav (home/explore/saved links + `LocaleSelector` + `MobileMenu` hamburger on mobile); `FacetMenu`/`SelectMenu` are trigger-button + popover dropdowns built on the `useDropdown` hook (multi-select `Chip` grids and single-select respectively). `Footer/` is the globally mounted site footer (Privacy/Terms/Contact links + social links, reads locale via `useLocale`); `LegalPage/` renders a localized legal document (own `TopBar` + rich sections from `content/legal/`) and backs the Privacy/Terms routes; `StaticPage/` is a shared flat-text page scaffold (`TopBar` + body) whose component has no importer today — only its stylesheet is live (`Contact.module.css` composes `.page`/`.main`/`.title`/`.body` from it) — kept as a scaffold for future static pages. The themed form controls back the organizer submit/edit form (`EventSubmit/`), replacing native `datetime-local`/`<select>`/`<input type="file">`: `DatePicker/` is a calendar + time popover built on `useDropdown` (date/grid helpers in `utils.ts`, literals in `constants.ts`), `SelectField/` is a single-select listbox popover over `ChipOption`s, `FileField/` is a file-picker + preview shell for the Cloudinary image upload.
- **Locale-prefixed routing** — every route in `App.tsx`'s `ROUTE_DEFS` is registered twice: once at its bare `ROUTES.*` path (Estonian) and once under a `/:locale` prefix (`localePrefixedPattern`), so `/en/...`/`/ru/...` reach the same element. Two route classes: Home (`/`) and `EventDetail` (`/events/:id`) are `noRedirect: true` — the two public SEO routes, whose bare path always renders Estonian and never redirects, regardless of any stored preference (crawler/prerender stability). Every other route is wrapped in `BareLocaleGate`, which redirects a bare visit to the stored preference's prefixed URL when that preference (`getStoredLocale()`, distinct from `getLocale()`'s UI-default fallback) is explicitly set to something other than Estonian; a first-time visitor with no stored preference is left on the bare path. An unrecognized `:locale` segment (e.g. `/xx/...`) falls back to Estonian content without redirecting the URL. `useRouteLocale()` (`frontend/src/hooks/`) resolves the current `:locale` param the same way, for callers that just need the value. `useLocaleMutation` resolves its `locale` from the URL segment when present, else from the stored preference (or Estonian for `publicRoute: true` callers — Feed/Landing/EventDetail); switching locale navigates to the equivalent prefixed path (`localizedPath`/`stripLocalePrefix` in `utils.ts`) in addition to its existing `localStorage`/`PATCH /users/me` persistence. `Protected`/`OrganizerProtected` guards sit inside this wrapper, unaffected by it.
- Tests co-located as `Name.test.tsx` / `Name.test.ts` beside each subject file. Shared test helpers and factories live in `frontend/src/test/` (`setup.ts`, `utils.tsx`). Stack: Vitest + @testing-library/react + jsdom.
- Shared CSS base classes in `frontend/src/components/shared/`: `Card.module.css` (`.card`, `.cardAccentTop`, `.cardDangerTop`, `.cardPage`), `Button.module.css` (`.btnPrimary`, `.btnOutline`), `Menu.module.css` (`.menu`, `.menuPop`, `.triggerButton`/`.triggerButtonActive`, `.triggerInline`/`.triggerInlineActive` — the popover/trigger chrome shared by `FacetMenu`, `SelectMenu`, `MobileMenu`, `DatePicker`, and `SelectField`), and `Animations.module.css` (`.spin`, `.breathe`, `.rise` + their `@keyframes`, tuned per call site via `--spin-duration` / `--breathe-duration` / `--rise-distance` custom properties). Compose from these via CSS Modules `composes` — never copy-paste the same card/button/menu rules into route or component stylesheets. Component CSS composes from `'../shared/X.module.css'`; route CSS from `'../../components/shared/X.module.css'`.
- API client in `frontend/src/api/client.ts` — `api` (consumer session token) plus a thin `organizerApi` wrapper that passes `{ organizer: true }` on every call, so organizer routes/hooks never have to remember the flag; a 401 clears the matching token and redirects to `/login` or `/organizer/login` respectively. `FormData` bodies (the image upload) skip JSON stringification and the explicit `Content-Type`. React Query used for server state (`@tanstack/react-query`).
- Custom hooks in `frontend/src/hooks/`: `useAuth.ts` (live auth-state subscription), `useLocale.ts` (live locale subscription, mirroring `useAuth` — lets the globally mounted `Footer` re-render on a locale switch from any page), `useLogout.ts` (clear token + redirect), `useMagicLinkRequest.ts` (request-link mutation), `useFeedback.ts` (feedback signal dispatch), `useLocaleMutation.ts` (locale-switch mutation), `useContactSubmit.ts` (contact-form submit mutation), `useDropdown.ts` (open/close + outside-click + Escape + focus + mobile-flip for trigger-button popovers), `useToast.ts` (transient success/error toast state with auto-clear), plus the organizer-track equivalents `useOrganizerAuth.ts` (live organizer-session subscription, backs `OrganizerProtected`), `useOrganizerLogout.ts`, and `useOrganizerEventForm.ts` (submit/edit form state for `EventSubmit/`).
- Auth helpers in `frontend/src/lib/auth.ts` (token + locale storage, `isAuthenticated()`, `beginLogout()`/`isLoggingOut()`, a `subscribeAuth()` emit/subscribe store that `useAuth()` reads, and a parallel `getLocale()`/`subscribeLocale()` store that `useLocale()` reads), with `frontend/src/lib/organizerAuth.ts` mirroring it for the organizer track (its own `ORGANIZER_TOKEN_KEY` storage key, `isAuthenticatedOrganizer()`, `beginOrganizerLogout()`/`isOrganizerLoggingOut()`, `subscribeOrganizerAuth()` behind `useOrganizerAuth()`; no locale store of its own — locale stays in `auth.ts`) — the two token stores never share a key, matching the separate backend salts. Components must go through `useAuth()`/`useOrganizerAuth()` — never read `isAuthenticated()` directly in render, or auth changes won't re-render.

## i18n

**Single source of truth:** `shared/i18n/{en,et,ru}.json` — split into `"ui"` (frontend strings) and `"email"` (backend digest/magic-link strings). `shared/personas.json` holds persona names + vibes per locale. `shared/app-config.json` holds cross-stack scalars and taxonomies. `shared/calendar.json` holds localized `day_names`/`month_names` (generated into the backend's `DAY_NAMES`/`MONTH_NAMES`).

**Workflow:** Edit the JSON files in `shared/` → run `python scripts/generate_shared.py` → commit both the JSON and the updated `_generated` files. Never edit `_generated/` directly.

- **Frontend** — `frontend/src/i18n.ts` re-exports helpers (`t`, `ti`, `personaName`, `personaVibe`) and imports strings from `frontend/src/_generated/i18nData.ts`. `frontend/src/constants.ts` imports `LOCALES`, `PERSONAS`, TTL, and weight thresholds from `frontend/src/_generated/sharedConstants.ts`.
- **Backend** — `backend/app/i18n.py` re-exports helpers (`t`, `ti`, `day_name`, `month_name`) and imports `TRANSLATIONS`, `DAY_NAMES`, `MONTH_NAMES` from `backend/app/_generated/i18n_data.py`. `backend/app/constants.py` imports cross-stack scalars and frozensets from `backend/app/_generated/shared_constants.py`.
- **Email styling** — `backend/app/email/styles.py` holds `EMAIL_CSS` (shared progressive-enhancement `<style>` block) plus `S_*` inline-style constants, split into shared page chrome (reused by every email type) and per-email groups (event card for the digest, body/note styles for the magic link). `backend/app/email/templates.py` holds the shared `EMAIL_DOCUMENT` page shell (header/content/footer row placeholders) plus per-email header/body/footer templates that fill those slots, and the digest's `EVENT_*` card markup. New email types add their own header/body/footer templates and reuse `EMAIL_DOCUMENT` rather than duplicating the shell.
- **Email digest** — `backend/app/email/digest.py` handles data formatting + assembly and Resend delivery, filling `EMAIL_DOCUMENT` with `DIGEST_HEADER`/`DIGEST_FOOTER`. The digest matches the site's visual design: each event block includes its `image_url` (escaped, falls back to a plain color band when absent) and the header carries an "open feed" button linking to the frontend app (`feed_url`). HTML only, no plain-text part. All subjects, labels, and day/month names resolved via `app/i18n.py`. New email types must follow the same three-file split: presentation CSS in `styles.py`, markup in `templates.py`, assembly + delivery in a dedicated module.
- **Magic-link email** — `backend/app/email/magic_link.py` (`build_magic_link_html`/`build_magic_link_text`) fills `EMAIL_DOCUMENT` with `MAGIC_LINK_HEADER`/`MAGIC_LINK_BODY`/`EMAIL_FOOTER_BRAND`, matching the digest's visual system (dark page, gold CTA button). Sends both an HTML and a plain-text part — unlike the digest, since this is a transactional/deliverability-sensitive send. Called from `app/auth/email.py::send_magic_link`, which stays on a raw (non-retrying) `httpx` call for the reason documented inline (see `docs/security.md`'s Auth section).
- **Contact email** — `backend/app/email/contact.py` (`send_contact_message`) delivers a contact-form submission to the owner inbox (`settings.CONTACT_TO_ADDRESS`, `reply_to` set to the sender) via Resend. This is **internal-only** mail (not user-facing branding), so it deliberately skips the `EMAIL_DOCUMENT` shell / `styles.py` / `templates.py` split and inlines escaped plain markup — the documented exception to the three-file rule. Falls back to log-only when `RESEND_API_KEY` is unset. Called from `app/routers/contact.py::submit_contact` (`POST /contact`, honeypot + `RATE_LIMIT_CONTACT`), which swallows send errors so no email failure surfaces to the caller.
- **Drift guard** — `backend/tests/test_generated_sync.py` runs the generator into a temp dir and asserts byte-identical output. If it fails: `python scripts/generate_shared.py` and commit.

## SEO: meta tags, structured data, prerendering

- **`useSeoMeta`** (`frontend/src/hooks/useSeoMeta.ts`, pure builder `buildSeoMeta`) — every route's `<title>`/`<html lang>`/default `noindex`; Landing and `/events/:id` additionally pass `indexable: true` for OG tags, a self-referential canonical, and hreflang alternates (`en`/`et`/`ru` + `x-default`). Every other route goes through the thin `useStaticSeoMeta` wrapper (`frontend/src/hooks/useStaticSeoMeta.ts`). Rendered via `<SeoTags meta={...} jsonLd={...} />` (`frontend/src/components/SeoTags/`), a thin `react-helmet-async` shell.
- **Structured data** — `frontend/src/lib/structuredData.ts` builds schema.org JSON-LD typed against `schema-dts`: `buildEventJsonLd` (event detail — never emits `organizer` or `offers.availability`, since neither is backed by real data) and `buildWebsiteJsonLd` (Landing — `name`/`url`/`inLanguage` only).
- **Build-time prerender pipeline** (`frontend/scripts/prerender.ts`) — runs as the last step of `npm run build` (after `tsc --noEmit && vite build`), so `vercel build` produces it automatically. It fetches every published event id from `GET /public/prerender-events` (`backend/app/routers/public.py::prerender_events` — the single source of truth for "what's published", also reused by `sitemap.xml` generation), boots the just-built `dist/` under `vite preview` (its `preview.proxy` config in `vite.config.ts` forwards `/api` to a real backend — `PRERENDER_API_ORIGIN` env var, defaulting to the same Render origin `vercel.json`'s `/api/:path*` rewrite already targets), and drives it with Playwright (bounded worker pool, `PRERENDER_CONCURRENCY` in the script) to snapshot Landing + every published `/events/:id`, across all three locale-prefixed URL variants. Each snapshot is written to `dist/<locale-prefix>/.../index.html` — the same directory-index shape Vercel's static file server resolves before falling through to a rewrite, so a prerendered path is served as-is without touching `vercel.json`. A page is considered "rendered" once its `<link rel="canonical">` is attached (only present once `useSeoMeta`'s `indexable` flips true, which for `/events/:id` only happens after the event has actually loaded — see `EventDetail.tsx`). The script fails the build (non-zero exit) if the published-events fetch fails or if any target can't be reached/rendered within its timeout.
- **The SPA fallback shell** — `dist/index.html` (the plain CSR entry `vite build` produces) is copied to `dist/app-shell.html` *before* the bare-Estonian Landing snapshot overwrites `dist/index.html`. `vercel.json`'s catch-all rewrite (`/((?!api/|_vercel/).*)`) targets `app-shell.html`, not `index.html`, so every non-prerendered route (`/explore`, `/saved`, `/settings`, etc.) keeps serving the untouched CSR shell rather than a stale/mismatched snapshot.
- **Local dry run** — `PRERENDER_API_ORIGIN=http://127.0.0.1:8000 npm run build` (with a local backend running) exercises the full pipeline against dev data instead of production.
