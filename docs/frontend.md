# Frontend

What's in here: the routes/components/hooks folder structure, the i18n data pipeline (shared JSON → generated TS/Python), and email rendering. SEO and prerender live in `docs/seo.md`.

Read this before touching `frontend/src/routes/`, `frontend/src/components/`, `frontend/src/hooks/`, `frontend/src/lib/`, `frontend/src/content/`, `frontend/scripts/generate-icons.ts`, `shared/i18n/`, or `backend/app/email/`.

## Frontend Structure

Each component and route lives in its own folder containing `Name.tsx`, `Name.module.css`, and a one-line `index.ts` barrel (`export { default } from './Name'`). The barrel keeps import strings short — callers write `./components/EventCard`, not `./components/EventCard/EventCard`. **Exceptions** (no own stylesheet): `Privacy/` and `Terms/`, being one-line wrappers over `LegalPage` (which owns the styling); `SeoTags/`, being a thin `react-helmet-async` shell with no rendered DOM to style; `AdminApp/`, being a pure pathname dispatcher (see below) that renders no styled DOM of its own; `AdminThemeToggle/`, which fully delegates rendering to `SelectMenu`; `ChevronIcons/`, being the shared prev/next inline-SVG chevrons `DatePicker`/`DateRangeMenu` page months with (styled by their consumers). (Those six are the complete set that need no styles at all — `AdminApp/`, `Privacy/`, `Terms/`, `AdminThemeToggle/`, `ChevronIcons/`, `SeoTags/`. The other folders without a stylesheet are the top-bar family — `TopBar/`, `OrganizerTopBar/` and the bar sub-components `BarLogo/`, `BarNav/`, `PulseChip/`, `BarSearch/`, `AccountMenu/`, `PrefsMenu/` — styles itself from the shared `components/shared/Bar.module.css` rather than carrying its own; `DialMark/` and `MobileMenu/` have their own.) **Route-private subcomponents skip the own-folder/barrel convention entirely** — they sit as a bare `Name.tsx` beside their parent route/component instead, since nothing outside that parent ever imports them and a folder+barrel would be indirection with no caller to shorten: `Explore/UpsellCard.tsx`, `AdminPipeline/ConfirmRunModal.tsx`, `AdminPipeline/PipelineRunBreakdown.tsx`, `RichTextEditor/icons.tsx` (toolbar glyphs, not a component). The pattern is consistent and intentional — don't promote one to a folder without a second, cross-parent importer showing up.

`Contact/` renders its own `TopBar` + the contact form (via `useContactSubmit`). `Faq/` (`/faq`) does **not** reuse `LegalPage`: it copies its `TopBar` wiring, per-locale loader effect (active locale → `en` → error `PageState`) and structured `renderInline` approach, but renders its own layout — header + section jump-nav, one closed `<details>` per question (answers always in the DOM, for the prerender), and a closing contact CTA — from a `FaqDoc` loaded per-locale from `frontend/src/content/faq/` (`types.ts`, `loaders.ts`'s `FAQ_LOADERS`, `faq.en.ts`/`faq.et.ts`/`faq.ru.ts`, one lazy chunk each; React never renders `open`, so the summary still toggles the item. The scroll is `smooth`, or `auto` under reduced motion, and `scroll-margin-top` keeps the target clear of the sticky TopBar. A hash that isn't a doc section or item id is ignored. In-app `#` link clicks are native fragment jumps that land before the effect runs, so `Faq.module.css` sets `scroll-behavior: smooth` on `html:has(.page)` while the page is mounted. `index.css`'s reduced-motion block forces it back to `auto`. - **Locale-prefixed routing** — every route in `App.tsx`'s `ROUTE_DEFS` is registered twice: once at its bare `ROUTES.*` path (Estonian) and once under a `/:locale` prefix (`localePrefixedPattern`), so `/en/...`/`/ru/...` reach the same element. Two route classes: Home (`/`), `Explore` (`/explore`, issue #236), `EventDetail` (`/events/:id`) and `Faq` (`/faq`, issue #491) are `noRedirect: true` — the four public SEO routes, whose bare path always renders Estonian and never redirects, regardless of any stored preference (crawler/prerender stability). Every other route is wrapped in `BareLocaleGate`, which redirects a bare visit to the stored preference's prefixed URL when that preference (`getStoredLocale()`, distinct from `getLocale()`'s UI-default fallback) is explicitly set to something other than Estonian; a first-time visitor with no stored preference is left on the bare path. An unrecognized `:locale` segment (e.g. `/xx/...`) falls back to Estonian content without redirecting the URL. `usePathLocale()` (`frontend/src/hooks/`) resolves the current URL's locale the same way (prefix, else Estonian — read from the pathname, so it also works outside `<Routes>`), for callers that just need the value: the `Footer`, `useLocaleMutation`, and the switcher-less pages (`Login`, `OrganizerLogin`, `AuthVerify`, `OrganizerVerify`, `OrganizerClaimVerify`, `Unsubscribe`, `NotFound`), so a page and the footer under it always share a language (issue #497). Because those switcher-less pages read the language from the URL alone, every user-facing link the backend puts in an email (magic-link/organizer/claim verify, Google-link confirmation, claim-resolution, report-outcome, digest incl. its unsubscribe link) carries the recipient's locale prefix via `app/email/links.py` (`localized_path`/`frontend_url`, the backend counterpart of `localizedPath`; ET bare) — never a bare `f"{settings.FRONTEND_URL}..."` (issue #499). The admin-only report notification and the digest's `List-Unsubscribe` header (backend `/email/unsubscribe`) stay unprefixed. `useLocaleMutation` resolves its `locale` from the URL segment when present, else from the stored preference (or Estonian for `publicRoute: true` callers — Feed/Landing/Explore/EventDetail/Faq); switching locale navigates to the equivalent prefixed path (`localizedPath`/`stripLocalePrefix`, defined in `frontend/src/lib/urlLocale.ts` and re-exported through `utils.ts` — the one deliberate exception to "all shared helpers in `utils.ts`", explained in that module's own comment) in addition to its existing `localStorage`/`PATCH /users/me` persistence. `Protected`/`OrganizerProtected` guards sit inside this wrapper, unaffected by it.

- API client in `frontend/src/api/client.ts` — `api` (consumer track) plus thin `organizerApi` and `adminApi` wrappers that pass `{ organizer: true }` / `{ admin: true }` on every call, so those routes/hooks never have to remember the flag, and `adminStream()` for the NDJSON job triggers. Every request goes out with `credentials: 'include'`; the session itself is an httpOnly cookie the JS never sees (`docs/adr/0001-session-tokens-in-httponly-cookies.md`), so there is no token in `localStorage` to attach. A 401 means "session expired" on every path but `POST /admin/auth/login` (`NO_SESSION_REDIRECT_ON_401` — there it means "wrong credentials", and must reach the login form as a real `ApiError`); `handleSessionExpiry401` clears the matching track's *signed-in hint* and redirects to `/login`, `/organizer/login` or `/admin/login`. `FormData` bodies (the image upload) skip JSON stringification and the explicit `Content-Type`. React Query used for server state (`@tanstack/react-query`).
- Custom hooks in `frontend/src/hooks/`: `useAuth.ts` (live auth-state subscription), `useLogout.ts` (clear token + redirect), `useMagicLinkRequest.ts` (request-link mutation), `useFeedback.ts` (feedback signal dispatch), `useLocaleMutation.ts` (locale-switch mutation), `useContactSubmit.ts` (contact-form submit mutation), `useDropdown.ts` (open/close + outside-click + Escape + focus + mobile-flip for trigger-button popovers), `useToast.ts` (transient success/error toast state with auto-clear), `useEventReport.ts` (report-modal open/close + sign-in gate + cache invalidation for `ReportModal`; caller supplies `authed`/`onLoginRequired`), `useEventCardNav.ts` (one memoized `{localePath, authed, onLoginRequired}` object resolved by each card list — Feed/Explore/Saved — and passed as `EventCard`'s `nav` prop, so no card subscribes to the router or auth store itself), `useFitsViewport.ts` (whether an element at its CSS sticky `top` fits the viewport — gates EventDetail's wide-band sticky rail), `usePrefersReducedMotion.ts` and `useResolvedTheme.ts` (live subscriptions — the reduced-motion media query, and `lib/theme.ts`'s resolved light/dark value, re-rendering on an OS flip, another tab's write, or an override expiring), `useGoogleSignInError.ts` (Login/OrganizerLogin's shared Google-callback error banner — reads the error param once, then strips it from the URL), `useBarScrolled.ts` (the top bar's condense state — past 24px, back under 4px), `useScrollLock.ts` (locks body scroll while `MobileMenu`'s drawer is open), and the locale-routing quartet `usePathLocale.ts` (the current URL's locale — its `/en`/`/ru` prefix, else Estonian — read from `useLocation`, so it works outside `<Routes>`; backs the `Footer`'s labels, `useLocalePath`, `useLocaleMutation` and the switcher-less auth/verify/unsubscribe/NotFound pages), `useLocalePath.ts` (locale-prefix an internal `to` against the current URL — every `<Link to>`/`navigate()` target goes through it), `useLocaleNavigate.ts` (the `useNavigate()` wrapper that does the same for programmatic navigation), and `useLocalLocale.ts` (local mirror of the global locale for the switcher routes, so their own tree re-renders immediately). Plus the organizer-track equivalents `useOrganizerAuth.ts` (live organizer-session subscription, backs `OrganizerProtected`), `useOrganizerLogout.ts`, `useOrganizerEventForm.ts` (submit/edit form state for `EventSubmit/`), `useOrganizerContactSubmit.ts` (the `/organizer/contact` mutation, parallel to `useContactSubmit`), `useClaimEventEdit.ts` (form state + save for the claim-editing surface, `ClaimEventEdit/`), and the admin-track ones `useAdminAuth.ts`/`useAdminLogin.ts`/`useAdminLogout.ts` (a third, independent auth track over `lib/adminAuth.ts`) and `useTriggerRun.ts` (streams one `AdminPipeline` trigger's NDJSON run, tracking cold-start/streaming/disconnected state). `useSeoMeta.ts`/`useStaticSeoMeta.ts` are covered in `docs/seo.md`.
- Auth helpers in `frontend/src/lib/auth.ts` (the **signed-in hint** + locale storage, `setSignedInHint()`/`clearSignedInHint()`/`isAuthenticated()`, `beginLogout()`/`isLoggingOut()`, a `subscribeAuth()` emit/subscribe store that `useAuth()` reads, and the stored locale preference via `getLocale()`/`getStoredLocale()`/`setLocale()`), with `frontend/src/lib/organizerAuth.ts` and `frontend/src/lib/adminAuth.ts` mirroring it for the other two tracks (own `ORGANIZER_SIGNED_IN_HINT_KEY`/`ADMIN_SIGNED_IN_HINT_KEY` storage keys, `isAuthenticatedOrganizer()`/`isAuthenticatedAdmin()`, `beginOrganizerLogout()`/`isOrganizerLoggingOut()`, `subscribeOrganizerAuth()` behind `useOrganizerAuth()`; no locale store of their own — locale stays in `auth.ts`) — the three hint stores never share a key, matching the separate backend salts. The hint is a `'1'` marker only: the real session is an httpOnly cookie (`docs/adr/0001`), so `isAuthenticated()` answers "should the UI render as signed in", never "is this request authorized" — the backend decides that on every call, and a stale hint only costs one 401-and-redirect. Components must go through `useAuth()`/`useOrganizerAuth()` — never read `isAuthenticated()` directly in render, or auth changes won't re-render.

## i18n

**Single source of truth:** `shared/i18n/{en,et,ru}.json` — split into `"ui"` (frontend strings) and `"email"` (backend digest/magic-link strings). `shared/personas.json` holds persona names + vibes per locale. `shared/app-config.json` holds cross-stack scalars and taxonomies. `shared/calendar.json` holds localized `day_names`/`month_names` (generated into the backend's `DAY_NAMES`/`MONTH_NAMES`).

**Workflow:** Edit the JSON files in `shared/` → run `python scripts/generate_shared.py` → commit both the JSON and the updated `_generated` files. Never edit `_generated/` directly.

- **Frontend** — `frontend/src/i18n.ts` re-exports helpers (`t`, `ti`, `personaName`, `personaVibe`) and imports strings from `frontend/src/_generated/i18nData.ts`. `frontend/src/constants.ts` imports `LOCALES`, `PERSONAS`, TTL, and weight thresholds from `frontend/src/_generated/sharedConstants.ts`.
- **Backend** — `backend/app/i18n.py` re-exports helpers (`t`, `ti`, `day_name`, `month_name`) and imports `TRANSLATIONS`, `DAY_NAMES`, `MONTH_NAMES` from `backend/app/_generated/i18n_data.py`. `backend/app/constants.py` imports cross-stack scalars and frozensets from `backend/app/_generated/shared_constants.py`.
- **Brand-asset generator** (`frontend/scripts/generate-icons.ts`, hand-run, not part of `npm run build`: `npx tsx scripts/generate-icons.ts`) — owns `public/favicon.svg` and rasterizes `favicon.ico`, `icon-96/192/512`, `icon-maskable-512`, `apple-touch-icon`, `email-mark.png` (path `EMAIL_BRAND_MARK_PATH`, shared with the backend via `shared/app-config.json`) and `og-fallback.png` through Playwright. Commit the regenerated binaries with the script change; geometry rules in `docs/design-system.md` §9 (the Dial bullet). The email header mark is `backend/app/email/brand.py::brand_mark_html()`, called by every builder that fills a `*_HEADER` template.
- **Email styling** — `backend/app/email/styles.py` builds one `EmailStyles` bundle (`EMAIL_STYLES`, read via `get_email_styles()`, ADR 0003): a light base palette with a `prefers-color-scheme: dark` override block (`_THEME_CLASS_RULES`, driving `e-*` class hooks in the templates), the shared progressive-enhancement `<style>` block, and the palette-dependent inline styles; theme-neutral geometry stays as module-level `S_*` constants. See `docs/design-system.md` §5's Email theming. `backend/app/email/templates.py` holds the shared `EMAIL_DOCUMENT` page shell (header/content/footer row placeholders) plus per-email header/body/footer templates that fill those slots, and the digest's `EVENT_*` card markup. New email types add their own header/body/footer templates and reuse `EMAIL_DOCUMENT` rather than duplicating the shell.
- **Email digest** — `backend/app/email/digest.py` handles data formatting + assembly and Resend delivery, filling `EMAIL_DOCUMENT` with `DIGEST_HEADER`/`DIGEST_FOOTER`. The digest matches the site's visual design: each event block includes its `image_url` (escaped, falls back to a plain color band when absent) and the header carries an "open feed" button linking to the frontend app (`feed_url`). HTML only, no plain-text part. All subjects, labels, and day/month names resolved via `app/i18n.py`. New email types must follow the same three-file split: presentation CSS in `styles.py`, markup in `templates.py`, assembly + delivery in a dedicated module.
- **Email markup uses plain `str.format()` constants, with no templating engine.** Jinja2 or similar would add a dependency for what string constants already do. Apply the same three-file split to any future rendering feature, such as a report export.
- **Magic-link email** — `backend/app/email/magic_link.py` (`build_magic_link_html`/`build_magic_link_text`) fills `EMAIL_DOCUMENT` with `MAGIC_LINK_HEADER`/`MAGIC_LINK_BODY`/`EMAIL_FOOTER_BRAND`, matching the digest's visual system (same light-base/dark-override bundle, gold CTA button). Sends both an HTML and a plain-text part — unlike the digest, since this is a transactional/deliverability-sensitive send. Called from `app/auth/email.py::send_magic_link`, which sends through the single-attempt `send_resend_email()` (`app/email/resend.py`) rather than the retrying `http_post` — see `docs/conventions.md`'s Retry logic exceptions.
- **Contact email** — `backend/app/email/contact.py` (`send_contact_message`) delivers a contact-form submission to the owner inbox (`settings.CONTACT_TO_ADDRESS`, `reply_to` set to the sender) via Resend. This is **internal-only** mail (not user-facing branding), so it skips the `EMAIL_DOCUMENT` shell and uses plain markup — the `CONTACT_HTML_BODY`/`CONTACT_TEXT_BODY` `.format()` constants in `templates.py`, assembled (escaped) in `contact.py` and sent via the shared `send_resend_email()` (`app/email/resend.py`). Falls back to log-only when `RESEND_API_KEY` is unset. Called from `app/routers/contact.py::submit_contact` (`POST /contact`, honeypot + `RATE_LIMIT_CONTACT`), which swallows send errors so no email failure surfaces to the caller.
- **Drift guard** — `backend/tests/test_generated_sync.py` runs the generator into a temp dir and asserts byte-identical output. If it fails: `python scripts/generate_shared.py` and commit.
